psql -U postgres -c '\du'   -- ดูคอลัมน์ Superuser / Create DB
③ schema.sql apply ซ้ำได้ไหม? ✅ ได้จริง ยืนยันแล้ว — ทีมนับใน backend/schema.sql: ENUM 13 ตัวห่อ duplicate_object + 1 ALTER TYPE … ADD VALUE IF NOT EXISTS + 35 CREATE TABLE IF NOT EXISTS. รันซ้ำไม่พัง ตามที่น้องเคลม 👍

⑤ .env.webtest ห้าม commit ✅ ปลอดภัยแล้ว — ทีมปิดรู .gitignore ให้แล้ว (ดูกล่องแดงบนสุด). .env.webtest จะถูก ignore อัตโนมัติ. แค่ git pull ก่อนเริ่ม
⚠️ ② กับดัก 3 ตัวในแผน (มองไม่เห็นตอนนี้ แต่จะพังตอน apply)
กับดัก #1 — schema.sql ไม่ได้ระบุ schema → ตารางจะไปลง public ไม่ใช่ mes_web_test
ทุก CREATE TABLE ในไฟล์เป็นชื่อเปล่า ไม่มี SET search_path ในไฟล์เลย. ถ้ารัน psql -f schema.sql เฉยๆ ตารางจะไปลง search_path default (คือ public) แล้วชนของเดิม. ต้องบังคับ search_path ตอน apply: 
PGOPTIONS="-c search_path=mes_web_test" psql -U postgres \
     -d productiondb_20260721 -f backend/schema.sql
(ส่วน knex migrate ไม่มีปัญหานี้ — knexfile.js อ่าน DB_SCHEMA แล้ว set searchPath + schemaName ให้เอง)
กับดัก #2 — port ใน db.js กับ knexfile.js ไม่ตรงกัน
db.js (runtime) default port = 5432 · knexfile.js (migrate) default port = 15432. masked DB ของน้องอยู่ที่ 5432 → ต้องใส่ DB_PORT=5432 ชัดๆ ใน .env.webtest ไม่งั้น knex migrate จะยิงไป 15432 (ผิดตัว) แล้ว error/ค้าง.
กับดัก #3 — ลืม DB_SCHEMA=mes_web_test = app กับ migrate แยกกันคนละ schema
ถ้า .env.webtest ไม่ตั้ง DB_SCHEMA: db.js จะไม่ set search_path (default ว่าง → วิ่งไป public), ส่วน knexfile.js จะ default ไป mes_core — คนละที่กับ schema.sql อีก 3 ที่. ต้องตั้งให้ตรงกันทั้งหมด.
🔧 ③ ลำดับ build ที่ถูก (แก้จากสไลด์ให้ครบกับดัก)

0) pull โค้ดล่าสุด (รับ .gitignore ที่ทีมแก้)

git pull

1) สร้าง backend/envs/.env.webtest (จะถูก ignore อัตโนมัติแล้ว)

# คัดลอกจาก backend/envs/.env.test (มี key ครบ) แล้วแก้ค่าตามนี้
MES_ENV=test
DB_HOST=127.0.0.1
DB_PORT=5432              # ← masked DB อยู่ 5432 (กับดัก #2)
DB_NAME=productiondb_20260721
DB_SCHEMA=mes_web_test    # ← กันกับดัก #3 (db.js + knex อ่านตัวนี้)
DB_USER=...               # user ที่มีสิทธิ์บน DB นี้
DB_PASSWORD=...
MES_CORS_ORIGINS=http://localhost:5101,http://127.0.0.1:5101   # checklist #4

2) สร้าง schema

psql -U postgres -d productiondb_20260721 \
  -c "CREATE SCHEMA IF NOT EXISTS mes_web_test;"

3) apply schema.sql พร้อมบังคับ search_path (กับดัก #1)

PGOPTIONS="-c search_path=mes_web_test" psql -U postgres \
  -d productiondb_20260721 -f backend/schema.sql

4) รัน migration หลัง schema.sql เสมอ (ตามที่น้องเตือนไว้ในสไลด์ — ถูกแล้ว)

cd backend
export $(grep -v '^#' envs/.env.webtest | xargs)
npx knex migrate:latest

5) start + verify

node server.js
# health
curl -s localhost:5100/api/mes/health
# ยืนยันว่าตารางลงถูก schema จริง (ต้องได้ >30 ตาราง ไม่ใช่ 0)
psql -U postgres -d productiondb_20260721 \
